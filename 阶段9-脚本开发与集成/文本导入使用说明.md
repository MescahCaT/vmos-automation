# 文本导入代理与云机清单

两个脚本只读取本地文本、生成 JSON，不会连接 VMOS 或创建实例。导入代理时不会在屏幕上显示账号密码；覆盖已有 JSON 前会在原目录生成时间戳备份。输入文件支持 UTF-8、UTF-8 BOM、UTF-16、GB18030。

从项目根目录 `D:\000aaa_vmos自动化` 打开 PowerShell。路径有空格时请保留双引号。

## 1. 从文本导入代理组

文本每行按顺序填写 **代理组名、IP、端口、账户、密码**，以空格或 Tab 分隔；空行和 `#` 开头的说明行会忽略。例如：

```text
151 157.238.152.47 9820 example-user example-password
152 130.94.203.45 9820 another-user another-password
```

运行后给出路径：

```powershell
python -X utf8 .\阶段9-脚本开发与集成\import_proxies.py "D:\我的资料\代理清单.txt"
```

也可以不带路径，脚本会提示输入：

```powershell
python -X utf8 .\阶段9-脚本开发与集成\import_proxies.py
```

代理会按第一列名称写入 `配置文件/proxy_list.json` 的 `proxies` 数组，作为代理 `id`；已有同名代理会更新地址和认证信息，其余字段保留。所有导入代理必须携带中转：已有中转的组继续保留，缺失中转时自动沿用上次配置（首次从已有启用代理中查找），并将最近使用的中转记入 `default_transit`。找不到有效中转时停止导入，不会生成直连代理。新代理默认启用 SOCKS5、标准引擎0。请先核对源文本，特别是每行必须有五列；例如 `156130.94.203.28` 会因缺少分隔符而被拒绝。

如果明确需要复用一个现有代理的中转、引擎和 country/language/timezone，可显式指定：

```powershell
python -X utf8 .\阶段9-脚本开发与集成\import_proxies.py "D:\我的资料\代理清单.txt" --template-proxy proxy-004
```

新地址必须确实使用相同地区和时区时才复用该模板；否则不要加此参数。默认不猜地区，也不自动复制 GPS。创建入口强制完成国家/时区/语言/GPS同步，每组代理必须填写符合实际出口的 `region.country`、`region.language`、`region.timezone`；缺少或无效时在创建前停止，不会跳过地区初始化。GPS缺省按实际出口解析。当前144～161组的地区配置已按IP定位补齐；以后新增代理仍需填写自己的地区参数。

## 2. 从云机名称文本生成创建清单

首次使用时，先复制批量创建模板，填写自己的 `host_ip`、镜像和 `adiID` 等公共参数；已有本地清单时跳过，避免覆盖：

```powershell
Copy-Item .\阶段9-脚本开发与集成\batch_create.template.json .\阶段9-脚本开发与集成\batch10_create.example.json
```

`batch10_create.example.json` 和 `batch10_bindings.example.json` 会被脚本更新为实际清单，因此已加入 `.gitignore`，只在本地保存。

每行一个名称，名称第一个点前是代理组名。例如 `151.1` 中，完整名称是 `151.1`，代理组是 `151`：

```text
151.1
151.2
152.1
152.2
153.1
```

先运行上一步导入代理，再执行：

```powershell
python -X utf8 .\阶段9-脚本开发与集成\generate_devices.py "D:\我的资料\云机名称.txt"
```

省略路径时也会提示输入。脚本会检查名称及代理组是否有效，并生成/更新：

- `阶段9-脚本开发与集成/batch10_create.example.json`：每行生成一台，`user_name` 和 `remark` 都设为完整名称，`count` 自动设为名称行数；原有主机、镜像、adiID、分辨率、DNS 等公共参数保留。
- `阶段9-脚本开发与集成/batch10_bindings.example.json`：把完整云机名称对应到点前的代理组 ID。

## 3. 一条命令创建云机

生成清单后，在项目根目录直接执行：

```powershell
python -X utf8 .\创建云机.py
```

该命令会真正创建阶段9 `batch10_create.example.json` 中的云机，然后按 `batch10_bindings.example.json` 逐台执行：绑定SOCKS5及中转 → 设置国家 → 设置时区 → 设置语言 → 注入GPS → 重启回查 → 验证出口与连续网页 → 安装TikTok并回查包名。地区设置必须执行或回查已有完成记录。安装使用主配置 `配置文件/config.json` 的 `tiktok.apk_path/package_name`，当前为项目内 `tiktok-43-7-2.apk`；创建前校验文件及包名，已经安装则跳过上传。地区成功后即使网页测试失败也继续当前云机的本地安装；整体联网仍记失败，不会自动放行后续云机。

自动保存本批配置快照、APK元数据和结果到 `日志/create-时间戳-随机后缀`，遇到已有同名云机时停止。每台完整配置安装后再恢复原运行/停机状态，避免重复启动。创建、地区、联网、安装或恢复状态存在未确认/失败时退出码为1，后续云机停止。

这批云机已经创建过时，使用补配置命令，避免重复创建：

```powershell
python -X utf8 .\创建云机.py --configure-only
```

只处理一台可在后面加 `--name 144.1`。创建清单或绑定表需要另外指定时，分别使用位置参数 JSON 路径和 `--bindings JSON路径`。报告总览是任务目录中的 `batch_status.json`，其中 `system_configured` 为地区结果、`network_verified` 为联网结果、`tiktok_installed` 为安装结果、`install_status` 为安装或跳过状态、`state_restored/final_state` 为整个初始化任务最终状态。全部确认才算成功；每台的配置与安装详情分别为其ID子目录 `proxy_status.json`、`install_status.json`。代理报告记录安装前的阶段状态，整体最终运行/停机状态以 `batch_status.json` 为准。
