# 阶段7：素材上传与内容发布

更新时间：2026-11-24。阶段7.1“素材上传”已实现；TikTok 编辑、草稿及正式发布尚未实现。本工具只上传本地素材，不执行媒体扫描或发布。

## 支持规则

- 支持 `.mp4`、`.png`、`.jpg`、`.jpeg`，扩展名不区分大小写。
- 文件夹只处理首层普通文件，不递归子目录。
- 云机名必须与当前创建清单中的 `user_name` 完全一致。不带 `--host` 时默认使用 `阶段9-脚本开发与集成/batch10_create.example.json`；指定 `--host` 后读取 `主机配置/IP/batch_create.json` 和对应主机配置。
- 默认云端目录为 `/sdcard/DCIM/Codex/`；请求显式设置 `scan=false`。
- 已停机云机在上传期间启动，完成后尝试恢复停机；原本运行的云机保持运行。
- 上传成功且云机返回路径、文件大小均与预期一致后，才将本地源文件移入其父目录的 `已上传` 子目录。重名时追加 ` (1)` 等后缀；失败或未确认的源文件保留原位。
- 结果写入 `日志/upload-日期时间-随机值/`；指定 `--host` 时写入 `日志/IP/`。报告包括批次 `batch_status.json` 和每台云机的 `upload_status.json`。报告记录本地 SHA-256；云端完整性仅按接口返回的目标路径和文件大小确认，不执行云端哈希读取。

## 模式1：素材池分配

云机列表 TXT 每行一个云机名，可用空行或 `#` 开头的行作注释。程序按文件名排序，从素材目录首层为列表中的每台云机分配 `--count` 个不同文件；素材不足会在启动云机或上传前报错。

```powershell
python -X utf8 .\上传素材.py --pool "D:\素材\待上传" --devices "D:\资料\云机列表.txt" --count 1
```

指定主机时加 `--host`，例如：

```powershell
python -X utf8 .\上传素材.py --host 192.168.110.35 --pool "D:\素材\待上传" --devices "D:\资料\云机列表.txt" --count 1
```

`--count` 默认是 `1`。一个文件只分配给一台云机；上传成功后移入该素材所在目录下的 `已上传` 文件夹。

## 模式2：任务清单

任务清单为 UTF-8 文本，每行严格使用一个 Tab 分隔云机名和素材绝对路径，不写标题行。路径可以是单个受支持文件，或包含素材的文件夹；文件夹只上传首层受支持文件。文件夹中的不支持格式会跳过并记入报告。

```text
device-0001<TAB>D:\素材\video.mp4
device-0002<TAB>D:\素材\第二批
```

`<TAB>` 代表一个实际 Tab 字符。执行命令：

```powershell
python -X utf8 .\上传素材.py --host 192.168.110.35 --tasks "D:\资料\上传任务.tsv"
```

同一台云机不能被分配同名素材，以避免目标目录文件覆盖；重复指派同一云机和源文件也会在上传前拒绝。相同源文件若指派给多台云机，只有全部上传确认成功后才归档。

## 常用选项

- `--config PATH`：指定创建清单 JSON。
- `--host IPv4`：选择独立主机配置、设备映射和日志目录。
- `--destination PATH`：指定云端绝对目录，默认 `/sdcard/DCIM/Codex/`。
- `--workers N`：同时处理的云机数，默认 `1`。
- `--timeout N`：单文件上传超时秒数，默认 `600`。

上传使用每台云机独立 Control API 的 `POST /file/import`。工具不会连接内容发布界面，也不会调用媒体扫描接口。
