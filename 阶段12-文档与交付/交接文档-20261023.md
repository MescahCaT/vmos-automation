## 2. 最新代理匹配规则

- 代理组名只能由 ASCII 数字 `0-9` 组成。
- 同名代理重新导入时更新原记录；不同名称会新增独立记录，即使地址、端口、账号和密码相同也不会合并。
- 前导零保留，`123` 和 `00123` 是两个不同代理组。
- 已有历史代理不会自动改名或删除。
- 从云机名中首个点 `.` 或横线 `-` 前的部分提取全部 ASCII 数字作为代理组名；首个分隔符后的内容不参与匹配。
- 例如：`abc123.1`、`abc123.2`、`xyz123.9` 和 `abc123-1` 都匹配代理组 `123`；完整云机名和备注仍保留原样。
- 首个点或横线前没有数字、对应代理不存在或代理未启用时，清单生成失败且不覆盖原文件。

## 3. 代理导入和云机清单生成

代理文本每行格式：

```text
代理组名 IP 端口 账户 密码
```

导入代理：

```powershell
python -X utf8 .\阶段9-脚本开发与集成\import_proxies.py "D:\资料\代理清单.txt"
```

可用 `--workers N` 设置代理出口/地区查询并发数。

根据云机名称文本生成清单和绑定表：

```powershell
python -X utf8 .\阶段9-脚本开发与集成\generate_devices.py "D:\资料\云机名称.txt"
```

也可以省略路径，脚本会提示输入。改用带字母的新云机名后，必须重新运行此命令更新两个 JSON。

## 4. 主要操作指令

新建并完整初始化：

```powershell
python -X utf8 .\创建云机.py --workers 3
```

已有云机执行完整初始化：

```powershell
python -X utf8 .\创建云机.py --configure-only --workers 3
```

指定一台或多台已有云机：

```powershell
python -X utf8 .\创建云机.py --configure-only --names abc123.1 abc123.2 --workers 2
```

失败台候补重试一轮：

```powershell
python -X utf8 .\创建云机.py --configure-only --workers 3 --retry-failed
```

独立操作：

```powershell
python -X utf8 .\设置代理.py --names abc123.1 abc123.2 --workers 2
python -X utf8 .\设置地区.py --names abc123.1 abc123.2 --workers 2
python -X utf8 .\安装TK.py --names abc123.1 abc123.2 --workers 2
```

更换清单或绑定表时，把 JSON 路径放在选项前，并加 `--bindings`：

```powershell
python -X utf8 .\设置代理.py "D:\资料\batch.json" --bindings "D:\资料\bindings.json" --names abc123.1 --workers 1
```

如果只有一个云机名称 TXT，先生成清单，再按 TXT 读取名称执行代理设置：

```powershell
python -X utf8 .\阶段9-脚本开发与集成\generate_devices.py "D:\0000ABC\PROMPT\1023\1023云机重配置代理.txt"

$names = Get-Content -LiteralPath "D:\0000ABC\PROMPT\1023\1023云机重配置代理.txt" |
  ForEach-Object { $_.Trim() } |
  Where-Object { $_ -and -not $_.StartsWith("#") }

python -X utf8 .\设置代理.py --names $names --workers 3
```

素材上传支持素材池和 Tab 任务清单两种模式，云机名须存在于当前创建清单：

```powershell
python -X utf8 .\上传素材.py --pool "D:\素材\待上传" --devices "D:\资料\云机列表.txt" --count 1
python -X utf8 .\上传素材.py --tasks "D:\资料\上传任务.tsv"
```

上传支持 MP4/PNG/JPG/JPEG，文件夹只读取首层，默认上传到 `/sdcard/DCIM/Codex/` 且关闭媒体扫描。成功确认后源文件归档到同级 `已上传`；报告位于 `日志/upload-*`。阶段7目前只实现上传，不包含 TikTok 发布。详细格式见 `阶段7-素材上传与内容发布/README.md`。

## 5. 当前初始化行为

- 根入口初始化按：代理请求 → 地区写入请求 → TikTok 安装 → 恢复原运行/停机状态。
- 根入口不做代理出口、网页联网、Android 地区属性或 GPS 的严格可用性核验；主要记录请求是否发出及安装包名是否确认。
- ROM、包名和状态恢复等待窗口最多 120 秒，窗口内不限轮数，约每 2 秒查询。
- 代理和地区请求结果不明确时记录日志并继续，不因这些结果阻止后续安装。
- TikTok 安装以目标包名确认；主机明确返回安装队列忙时先等待并回查，上传超时等不明确结果不重复上传。
- `--workers` 控制配置任务并发；主机安装队列仍可能限制实际上传并行度。
- `--retry-failed` 只在首轮全部任务收尾后重试失败台一轮，不会无限重试。

## 6. 登录TK当前完成标准

默认完成标准是：

```text
邮箱输入 → 邮箱验证码通过 → 输入并提交账号密码
```

密码提交请求被 TikTok 控制接口接受后即可判定该台登录完成并保留运行，不再要求后续个人资料页或页面跳转确认。TikTok 如果因自身问题回到登录页，脚本最多尝试返回，不会因此否定已确认的密码提交。

登录示例：

```powershell
python -X utf8 .\登录TK.py --accounts-file "D:\资料\账号.xlsx" --name 196.1 --workers 1
```

已经提交密码但旧批次未完成的设备，使用原批次目录只读续接，避免重新提交：

```powershell
python -X utf8 .\登录TK.py --accounts-file "D:\资料\账号.xlsx" --name 196.1 --workers 1 --resume --output-dir "D:\000aaa_vmos自动化\日志\原login目录"
```

严格要求本人资料页时才使用 `--completion profile`。
