========================
1. 基础信息
========================

版本要求:
- Android 10: vcloud_android10_edge_20260110及以上
- Android 13: vcloud_android13_edge_20260110及以上
- Android 15: vcloud_android15_edge_20260110及以上
- CBS: 1.1.1.10及以上

调用方式:

方式1 - 云机外HTTP调用(推荐):
- URL格式: http://{主机IP}:18182/android_api/v2/{云机ID}/{接口路径}
- 示例: http://192.168.1.100:18182/android_api/v2/EDGE12345678/activity/start

方式2 - 云机内HTTP调用:
- URL格式: http://127.0.0.1:18185/api/{接口路径}
- 示例: http://127.0.0.1:18185/api/activity/start

安全:
- 仅用于可信局域网,不要将18182/18185端口直接暴露到公网
- 先调用/base/version_info检查version_code和supported_list
- 同时检查HTTP状态和业务code,code=200才表示成功

方式3 - MCP调用(AI Agent集成, 需API版本1.0.7及以上):
- 局域网模式(创建云机时勾选了"启用局域网IP"): http://{云机IP}:18185/mcp/sse
- 非局域网模式(创建云机时未勾选"启用局域网IP"): http://{主机IP}:18182/android_api/v2/{云机ID}/mcp/sse
- 兼容客户端: Claude Code、Cursor、Codex、Gemini、通义千问、Kimi等
- Claude Code: claude mcp add --transport sse vmos-edge-control-api http://{云机IP}:18185/mcp/sse
- Cursor(.cursor/mcp.json): {"mcpServers": {"vmos-edge-control-api": {"url": "http://{云机IP}:18185/mcp/sse"}}}
- 通义千问/Kimi(MCP服务配置): {"mcpServers": {"vmos-edge-control-api": {"type": "sse", "url": "http://{云机IP}:18185/mcp/sse"}}}
- Gemini(~/.gemini/settings.json): {"mcpServers": {"vmos-edge-control-api": {"httpUrl": "http://{云机IP}:18185/mcp/sse"}}}

方式4 - CLI命令行工具(ve):
- Android设备上已预装在 /data/local/tmp/ve
- 其他平台(macOS/Windows/Linux)需从构建产物获取
- TCP端口: 18186
- 本机调用示例: ve -s 127.0.0.1 -l
- 使用 -s 连接设备进入交互模式: ve -s {云机IP}
- 单条命令: ve -s {云机IP} -l (列出接口)
- 参数: -l(列出接口) -s(连接设备) -j(JSON body) -f(文件) -v(版本) -h(帮助)
- 根据系统语言自动切换中英文

通用响应结构:
{
  "code": 200,          // 状态码,200为成功
  "data": {...},        // 业务数据
  "msg": "OK",          // 状态描述
  "request_id": "..."   // 请求唯一标识
}

常见错误码:
- 200: 成功
- 400: 参数错误
- 404: 接口不存在
- 500: 服务器内部错误

## 设置应用权限
POST /permission/set

参数:
- package_name (必填): 应用包名
- grant (必填): true=授予, false=撤销
- permissions (可选): 权限列表
- grant_all (可选): 是否授予所有请求的权限
- special_permission (可选): 是否授予特殊系统权限

特殊权限说明:
- 悬浮窗: 允许应用在其他应用上层显示
- 文件管理: 允许应用访问所有外部存储文件(Android 11+)
- 录屏: 自动允许录屏请求,跳过系统安全确认

请求示例:
{
  "package_name": "com.example.app",
  "grant": true,
  "permissions": ["android.permission.CAMERA"],
  "special_permission": true
}

返回示例:
{
  "code": 200,
  "data": {
    "package_name": "com.example.app",
    "grant": true,
    "success_count": 1
  },
  "msg": "OK",
  "request_id": "per0987654321"
}

## UI 节点操作
POST /accessibility/node

说明: 统一的节点操作接口，支持查找和执行动作，需要镜像版本20260113及以上

参数:
- selector (必填): 节点选择器
  - xpath (可选): XPath 表达式，优先级最高
  - text (可选): 节点文本，支持正则
  - content_desc (可选): 节点内容描述，支持正则
  - name (可选): 节点文本或内容描述，支持正则
  - resource_id (可选): 资源ID
  - package (可选): 包名
  - class (可选): 类名
  - clickable, enabled, scrollable, focusable, focused, selected, checkable, checked (可选): boolean状态
  - index (可选): 节点在父容器中的索引
  - center_x, center_y (可选): 节点中心坐标
- action (可选): 执行动作，不传则仅返回节点信息
  - 支持动作: click, long_click, set_text, scroll_forward, scroll_backward, copy, paste, cut, set_selection, clear_focus, focus
- action_params (可选): 动作参数
  - text: set_text动作的文本
  - start, end: set_selection动作的起始位置
- wait_timeout (可选): 等待超时时间(ms)，默认0
- wait_interval (可选): 重试间隔(ms)，默认1000
- action_index (可选): 对第几个匹配的节点执行动作，默认0

请求示例 (文本精准匹配并点击):
{
  "selector": {
    "text": "设置"
  },
  "action": "click"
}

请求示例 (XPath 匹配):
{
  "selector": {
    "xpath": "//node[@text='设置' and @clickable='true']"
  },
  "action": "click"
}

请求示例 (等待并设置文本):
{
  "selector": {
    "resource_id": "com.example:id/input"
  },
  "wait_timeout": 5000,
  "action": "set_text",
  "action_params": {
    "text": "Hello"
  }
}

返回示例:
{
  "code": 200,
  "data": {
    "success": true,
    "nodes": [
      {
        "text": "设置",
        "package": "com.android.settings",
        "class": "android.widget.TextView",
        "resource_id": "com.android.settings:id/title",
        "bounds": {"left": 100, "top": 200, "right": 300, "bottom": 400},
        "clickable": true
      }
    ],
    "action_performed": true
  },
  "msg": "OK",
  "request_id": "an123456"
}

26. AI Agent
========================

AI Agent是基于大语言模型(LLM)的智能任务执行引擎,能够自主理解用户意图并通过工具调用完成复杂的Android设备操作任务。

--- 配置管理 ---

## 设置API配置
POST /ai_agent/config_set

说明: 设置AI Agent的LLM API配置。至少需要提供一个配置参数,仅更新传入的字段。

参数:
- provider (可选): LLM提供商(如dashscope、openai、anthropic)
- model (可选): 模型名称(如qwen-flash、gpt-4o)
- base_url (可选): API基础URL
- api_key (可选): API Key
- max_turns (可选): 最大工具调用轮次,默认50
- system_prompt (可选): 系统提示词
- api_type (可选): API类型,chat_completions(默认)或responses

请求示例:
{
  "provider": "openai",
  "model": "gpt-4o",
  "base_url": "https://api.openai.com/v1",
  "api_key": "sk-xxxxx"
}

返回示例:
{
  "code": 200,
  "data": { "saved": true },
  "msg": "OK",
  "request_id": "ag123456"
}

## 获取API配置
POST /ai_agent/config_get

说明: 获取当前AI Agent的API配置信息。

参数: 无

返回示例:
{
  "code": 200,
  "data": {
    "provider": "openai",
    "model": "gpt-4o",
    "base_url": "https://api.openai.com/v1",

2) POST /android_api/v2/{db_id}/base/sleep
   body: {"duration": 2000}

示例B: 使用工作流执行一系列操作
1) POST /android_api/v2/{db_id}/workflow
   body: {
     "actions": [
       {"path": "activity/start", "params": {"package_name": "com.android.settings"}},
       {"path": "base/sleep", "params": {"duration": 2000}},
       {"path": "input/click", "params": {"x": 500, "y": 800}}
     ]
   }

示例C: 安装APK并启动
1) POST /android_api/v2/{db_id}/package/install_sync (multipart)
   file: app.apk
2) 等待返回成功
3) POST /android_api/v2/{db_id}/activity/start
   body: {"package_name": "com.example.app"}

示例D: 设置GPS并验证
1) POST /android_api/v2/{db_id}/location/set_data
   body: {"latitude": 39.9042, "longitude": 116.4074, "enabled": true}
2) GET /android_api/v2/{db_id}/location/get_data
3) 验证返回的latitude和longitude

示例E: 查找UI节点并点击
1) POST /android_api/v2/{db_id}/accessibility/node
   body: {
     "selector": {"text": "设置", "clickable": true},
     "action": "click"
   }

注意事项:
- 云机外调用使用/android_api/v2/{db_id}/前缀
- 云机内调用使用/api/前缀(localhost:18185)
- 工作流可以组合多个操作,按顺序执行
- 所有接口都返回request_id,便于追踪和排查
- 需要镜像版本支持的接口请确认版本号

========================
28. 错误处理建议
========================

1. 检查code字段判断成功/失败
2. 保存request_id用于问题排查
3. 参数错误时检查参数类型和值范围
4. 接口不存在时检查镜像版本是否支持
5. 操作失败时查看msg字段获取详细说明

========================
29. 性能优化建议
========================

1. 使用工作流组合多个操作,减少网络开销
2. 批量操作优先使用批量接口(如批量添加联系人)
3. 查找UI节点时使用精准条件,避免全屏扫描
4. 合理使用sleep避免操作过快导致失败
